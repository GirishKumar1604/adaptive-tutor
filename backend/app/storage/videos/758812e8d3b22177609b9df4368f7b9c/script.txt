1. What is Binary Search?
Binary search is a fast way to find an item in a sorted list by repeatedly cutting the search space in half. Instead of checking each element, we compare the target with the middle element and decide which half to keep. This reduces the number of checks dramatically.

2. Prerequisites
For binary search to work, the data must be sorted in ascending (or descending) order, and we need random access to any index, like an array. Without sorting, halving the list gives no guarantee of discarding the wrong half.

3. Algorithm Steps
We start with two pointers, low at the start and high at the end. While low ≤ high, we compute mid = ⌊(low+high)/2⌋. If the middle element equals the target, we’re done. If the target is smaller, we move high to mid‑1; otherwise, we move low to mid+1. The loop repeats until the target is found or the range is empty.

4. Worked Example
Consider the sorted array [2,4,7,10,14,18,21] and target 14. low=0, high=6, mid=3 (value 10). 14>10, so low becomes 4. Next mid=5 (value 18). 14<18, so high becomes 4. Now low=high=4, mid=4, value 14 – found! Only three comparisons were needed.

5. Time & Space Complexity
Each iteration halves the remaining range, so the number of steps grows with log₂ n, giving O(log n) time. The algorithm uses only a few integer variables, so its extra space is O(1). This makes binary search much faster than linear search for large datasets.

6. Pitfalls & Variants
Common mistakes include forgetting to sort the data, using integer overflow when computing mid, or off‑by‑one errors in the loop condition. Variants like lower‑bound and upper‑bound searches adjust the comparison to find the first or last occurrence of a value.
